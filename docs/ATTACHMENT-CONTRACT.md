# Attachment boundary v1 (L484)

This slice owns enrollment, inventory and reversible user hooks. Conversion and emitted runtimes stay in Omega and belong to L483. A converter or a callable binding alone does not qualify an automatic runtime hook. Parent L481 acceptance remains open.

`om discover` is read-only from any working directory. JSON separates `detection: DETECTED` from eligibility `state: DETECTED | SUPPORTED | ATTACHED | UNSUPPORTED | ERROR`. SUPPORTED requires a successful version check, compatible ABI and a verified reversible integration mechanism. ATTACHED additionally requires explicit enrollment and verified installed hook. Version probe failures are ERROR. Missing mechanisms are UNSUPPORTED with a reason. Production v1 has no qualified runtime hooks. `converter: NOT_AVAILABLE` means no converter protocol has been agreed with L483; this launcher never guesses a converter command.

The native Omega policy consumes six bytes per record: detected, version checked, ABI compatible, mechanism verified, enrolled, hook verified. Each byte is 0 or 1. Its one-byte response is ASCII 0/1/2/3/4 for DETECTED/SUPPORTED/ATTACHED/UNSUPPORTED/ERROR. Invalid flags and malformed records fail closed. The launcher must execute this seed-built policy; there is no C replacement policy. The C host boundary provides filesystem discovery, process isolation, notifications and installation transactions. The inspected seed exposes read/write/exit only. Missing Omega capabilities: directory enumeration; lstat/stat/readlink; open/mkdir/rename/unlink/fsync/flock; environment/argument access; fork/exec/wait/process groups; monotonic clock/poll; inotify; session detachment. These are frozen integration gaps, not converter work.

The registry is a descriptor table in `cli/registry.h`. New production adapters need version and ABI checks, a named hook, rollback and removal gates, and workload equivalence tests before enabling integration. Detection extensions can ship independently. The compile-time test registry adds `omega-fixture`, a cooperating shell runtime which explicitly consumes an Omega-owned registration. Its strict `--omega-attach-probe-v1` response is `OMEGA_ATTACH_FIXTURE_V1 native 1`. This boundary is fixture-only and is excluded from the shipping binary. It proves enrollment orchestration, never language conversion or integration with Python, C or another real runtime.

Enrollment changes only Omega-owned files under HOME: `.local/state/omega-attach/`, `.config/autostart/omega-attach.desktop` and, when bootstrap is invoked, `.local/lib/omega-attach/` plus `.local/bin/om` and `.local/bin/omg`. Existing commands or files are never overwritten. There is no checked extension in the inspected Omega console (`tools/omega.c`); an existing om command therefore causes bootstrap refusal. No shell startup files, environment-wide hooks, compiler shims, drivers, global packages, project folders or privileged services are edited.

Linux execution is the qualification target. The watcher uses inotify as a package-manager filesystem notification source and a periodic full bounded rescan as fallback. A manager can also call `om notify`. Notification bursts are debounced; version results are cached against executable metadata and invalidated on changes. Enrollment saves only whitelisted discovery roots and PATH, never the whole environment. Disabled enrollment retains configuration and removes active hooks. A desktop autostart entry is provided; actual graphical login execution is NOT_RUN. Headless reboot restart has no qualified mechanism yet. No systemd integration. macOS and Windows: NOT_RUN.

Final naming supersedes the initial brief: install `.local/bin/om` and `.local/bin/omg`, both targeting `.local/lib/omega-attach/om`. There is one saved configuration and watcher lock. Alias identity, lifecycle through either name, both collision cases and removal of both links are tested. Existing standalone Omega console source was inspected only; its absence of an extension handshake is not taken as authority to replace any command.

Discovery scope: registered executable names in absolute PATH directories, known per-user manager roots, explicitly set absolute manager environment variables and `.conda/environments.txt`. The registry covers Python, Node, Rust, Go, JVM, .NET, Ruby, PHP, C, C++, Swift, Julia, Lua, Perl, R, Zig, Elixir, Erlang, Haskell, OCaml, Dart, Deno and Bun. Active venvs and venvs already present on PATH retain separate environment identities even when their Python executable is a shared symlink. Other aliases deduplicate by language and executable inode. Ordinary project directories are never crawled. Unregistered venvs, arbitrary custom manager roots and future shell PATH directories outside these sources are not exhaustively discoverable. Relative PATH entries are skipped with a warning. Manager directory symlinks below the explicit roots are not recursively followed, to prevent cycles; executable symlinks and explicit symlinked roots work.

Bounds: 128 inventory records, 16 aliases each, 192 notification directories, manager traversal depth 5, 512 entries per manager directory, 4096 entries per executable directory and 16384 visited entries per scan. Limit hits produce partial-inventory warnings. Each version/ABI subprocess has a 250 ms wall deadline, 2 CPU seconds and 2047 output bytes; the scan's version-probe budget is 5 seconds, with remaining entries marked ERROR. Native policy responses have a 500 ms deadline. The default watcher merges event bursts over 300 ms, enforces a five-second minimum gap between scans, checks control state every 300 ms and rescans after at most 60 seconds without notifications. Successful version results are cached for up to 60 seconds against device/inode/size and nanosecond modification/change times. Filesystem events trigger fresh metadata checks; explicit notifications invalidate all cached versions. A manager proxy whose own executable metadata stays unchanged can retain a version until the 60-second cache expiry. Failures are retried. There are no default network requests. The subprocess boundary sanitizes environment, closes inherited descriptors, forbids filesystem writes and network sockets without privilege, and refuses probes if isolation cannot be established.

Enrollment snapshots only PATH and the 17 manager variables listed in `cli/registry.h`. A fresh invocation of attach explicitly refreshes that snapshot; a watcher cannot read future shell environments. Disable stops the watcher, clears active hooks and cached attachment claims, and retains enrollment configuration for enable. Revocation works with missing policy or damaged configuration. Owned installation files have local FNV-1a change fingerprints; these are modification checks, not release authentication or cryptographic provenance. Published evidence uses SHA-256. User-modified installation files, desktop entries and hook registrations are preserved and cause refusal. Uninstall restores prior file contents, modes, symlinks and directory presence in the tested isolated homes. Empty directories that existed before installation are retained. Power-loss recovery of an interrupted transaction is not qualified; synchronous failures are rolled back. Production attachment, a release distribution channel and unattended headless restart remain missing capabilities.
