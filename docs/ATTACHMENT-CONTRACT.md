# Attachment boundary v1 (L484)

This slice owns enrollment, inventory and reversible user hooks. Conversion and emitted runtimes stay in Omega and belong to L483. A converter or a callable binding alone does not qualify an automatic runtime hook. Parent L481 acceptance remains open.

`omega discover` is read-only from any working directory. JSON separates `detection: DETECTED` from eligibility `state: DETECTED | SUPPORTED | ATTACHED | UNSUPPORTED | ERROR`. SUPPORTED requires a successful version check, compatible ABI and a verified reversible integration mechanism. ATTACHED additionally requires explicit enrollment and verified installed hook. Version probe failures are ERROR. Missing mechanisms are UNSUPPORTED with a reason. Production v1 has no qualified runtime hooks. `converter: NOT_AVAILABLE` means no converter protocol has been agreed with L483; this launcher never guesses a converter command.

The native Omega policy consumes six bytes per record: detected, version checked, ABI compatible, mechanism verified, enrolled, hook verified. Each byte is 0 or 1. Its one-byte response is ASCII 0/1/2/3/4 for DETECTED/SUPPORTED/ATTACHED/UNSUPPORTED/ERROR. Invalid flags and malformed records fail closed. The launcher must execute this seed-built policy; there is no C replacement policy. The C host boundary provides filesystem discovery, process isolation, notifications and installation transactions. The inspected seed exposes read/write/exit only. Missing Omega capabilities: directory enumeration; lstat/stat/readlink; open/mkdir/rename/unlink/fsync/flock; environment/argument access; fork/exec/wait/process groups; monotonic clock/poll; inotify; session detachment. These are frozen integration gaps, not converter work.

The registry is a descriptor table in `cli/registry.h`. New production adapters need version and ABI checks, a named hook, rollback and removal gates, and workload equivalence tests before enabling integration. Detection extensions can ship independently. The compile-time test registry adds `omega-fixture`, a cooperating shell runtime which explicitly consumes an Omega-owned registration. Its strict `--omega-attach-probe-v1` response is `OMEGA_ATTACH_FIXTURE_V1 native 1`. This boundary is fixture-only and is excluded from the shipping binary. It proves enrollment orchestration, never language conversion or integration with Python, C or another real runtime.

Enrollment changes only Omega-owned files under HOME: `.local/state/omega-attach/`, `.config/autostart/omega-attach.desktop` and, when bootstrap is invoked, `.local/lib/omega-attach/` plus `.local/bin/omega`. Existing commands or files are never overwritten. There is no checked extension in the inspected Omega console (`tools/omega.c`); an existing omega command therefore causes bootstrap refusal. No shell startup files, environment-wide hooks, compiler shims, drivers, global packages, project folders or privileged services are edited.

Linux execution is the qualification target. The watcher uses inotify as a package-manager filesystem notification source and a periodic full bounded rescan as fallback. A manager can also call `omega notify`. Notification bursts are debounced; version results are cached against executable metadata and invalidated on changes. Enrollment saves only whitelisted discovery roots and PATH, never the whole environment. Disabled enrollment retains inventory for inspection and removes active hooks. Desktop autostart resumes the watcher on graphical login. Headless reboot restart has no qualified mechanism yet. No systemd integration. macOS and Windows: NOT_RUN.
