# Local pre-alpha installation

No downloadable release endpoint exists. The installer is local and offline. A shipping launcher needs Linux, libc and a seed-built policy; neither Python nor Node is needed to run it. Node is used only for the test harness. Building needs a C compiler and the qualified AArch64 Omega seed.

Build with `sh cli/build.sh /absolute/path/to/seed/out/omc`. Run `build/attach/om discover` to inspect installed language tools without changing files. After reviewing this pre-alpha build, `sh install/bootstrap.sh build/attach/om` installs the launcher and policy under the conventional user `.local` directories. It refuses an existing om command, including one elsewhere on PATH. If `.local/bin` is absent from the user's PATH, the installer reports that limitation and does not edit shell configuration. No one-command network bootstrap is currently published.

Once installed and reachable, `om attach` enrolls from any folder, inventories tools, installs only qualified user hooks and starts discovery in the background. `om status` shows inventory, enrollment and watcher health. `om disable` stops discovery and removes active hooks; `om enable` resumes; `om notify` requests a rescan after manager activity; `om uninstall` stops discovery and removes unchanged Omega-owned files, preserving preexisting content. Unexpected user edits cause refusal instead of deletion.

Production adapters currently report UNSUPPORTED because verified runtime hooks are missing. Discovery works independently of the unfinished converter. Desktop-login persistence is bounded Linux support; headless reboot persistence and real language attachment remain unqualified. No actual user service installation is performed by the test suite: all enrollment, bootstrap, watcher and autostart tests use isolated temporary homes.

The final command names are `om` (primary) and `omg` (equivalent alias). Bootstrap installs both links to one executable. Both use `.local/state/omega-attach`, so `om attach` and `omg status` observe the same watcher. A collision with either name refuses the whole installation. An unrelated `omega` command is preserved. Repeating bootstrap of an identical installed build leaves enrollment intact; differing builds or user-modified installation files require resolving the conflict first.

Executed platform: Linux AArch64 on Spark, including actual detached processes, inotify, file locks, unprivileged Landlock filesystem restrictions, seccomp socket restrictions and isolated filesystem restoration. Landlock ABI 3 or newer is required; unavailable probe isolation fails closed. Desktop entry syntax and replay of its watcher command are tested. An actual graphical login/logout cycle, headless reboot startup, macOS and Windows are NOT_RUN. This is a bounded discovery/enrollment milestone, not completed invisible integration with existing languages.

Run the whole attachment suite after building: `sh tests/attach/run.sh`. Tests require Node's built-in test runner, `/usr/bin/node` for the sandbox control, and `desktop-file-validate` for the desktop entry gate. Shipping commands do not depend on these test tools. Use `quiet-build sh cli/build.sh /absolute/path/to/seed/out/omc` on Spark.
