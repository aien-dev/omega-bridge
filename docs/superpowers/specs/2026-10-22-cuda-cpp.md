# CUDA C++ frontend for om

User scope: make om compile CUDA C++ source. This is not a CUDApp implementation-language migration.

## Implementation decision and first deliverable

Extend the existing qualified omega-bridge command, not a second compiler/installer. Handwrite a bounded CUDA C++ frontend in seeded Omega. It produces Omega source, compiled by the same source-born omc. Native GPU lowering is not qualified in the current compiler (L408); therefore build/run require the explicit `--target cpu-sim` for CUDA input, with no silent CPU fallback. This first deliverable is NOT full CUDA C++ support or completion of the user's overall request.

Accept one global one-dimensional unsigned-32 elementwise kernel: one writable unsigned-int pointer, one to four const unsigned-int pointers, and final unsigned-int length parameter. Body declares an unsigned-int index initialized to `blockIdx.x * blockDim.x + threadIdx.x`, guards `if (index < length)`, and writes exactly one `out[index] = expression`. Expressions use const inputs at index, the unsigned length, decimal U-suffixed literals, parentheses, +, -, *, &, ^, | with C++ precedence and wrapping uint32 arithmetic. All identifiers are resolved and renamed into short internal Omega names; source names never inject Omega text. Comments and whitespace supported, no preprocessing, macros, includes, templates, casts, floating point, synchronization, atomics, shared memory, arbitrary pointers, loops or host CUDA API. Unsupported syntax refuses with no output, never guesses.

The simulator has disjoint buffers, no aliasing. Binary stdin: little-endian uint32 blocks, threads, length; then initial output and each const input, each `length` uint32 words in signature order. blocks and threads each 1..4096, product <=4096, length <=4096. Execute covered indices only, preserve uncovered output, output exactly `length` uint32 words. Reject truncated/trailing input. Pure test harness protocol, not a CUDA ABI or GPU executable.

## Commands

`om check --from cuda-cpp source.cu` validates through real native lowering/compilation without execution.
`om build --from cuda-cpp --target cpu-sim source.cu -o executable`.
`om run --from cuda-cpp --target cpu-sim source.cu` inherits stdin and returns simulator status.

Existing Omega commands keep their syntax and behavior. CUDA target refusal must preserve existing output. Installation and uninstall include the frontend in their fixed file and integrity lists. No global install, service, GPU or driver changes.

## Acceptance and limits

First record baseline refusal of valid CUDA source. Then run compiled C++ original-source oracle with CUDA builtins supplied by a test-only host shim against native Omega-produced executables, exact uint32 output comparisons, signature/name/precedence/malformed/refusal and input-boundary cases. Require compiled behavioral mutants to disagree, no setup failure as a mutation kill. Run the whole existing project suite. Publish exact source/evidence, independently review. General C++, real GPU target, source diagnostics, additional CUDA features remain open and explicitly documented.
