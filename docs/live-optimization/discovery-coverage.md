## Qualification boundary

The native host integrator implements real current35B selection and logical
prefill scheduling, not full inference. Gate receipts live in
../../evidence/live35b-L739. It cannot issue device allocations/launches, mmap the
checkpoint, tokenize a conversation or listen on18139. L408/L605/L690 retain the
required foundations. Available software-binary32 native libraries are possible
oracle inputs, not permission for a silent CPU forward fallback or a duplicate
compiler/device/transport project.

A complete native target needs this dependency chain:
qualified seeded compiler -> native file/mapping and device ABI -> actual35B
loader/forward/weights/state ownership -> optimized native device kernels ->
HTTP/SSE tokenizer/tools continuation -> one admitted candidate train -> exact
controlled speed/quality configuration choice -> independent review -> parent
cutover and live readback. Host receipts prove only the currently implemented
selection/scheduling segment of that chain. No benchmark or model load was run.

The initial L739 environment could not see the host PID because /proc and
network are isolated. That was corrected immediately after inspecting namespace
identity and parent readback; it is not evidence of a stopped host service.
Original Git metadata, shared ledgers and gh guard state are read-only. Private
commit/bundle relay preserves work without changing the existing worktree or
other owners. aien-calc tool calls were refused by approval policy; no arithmetic
receipt or derived speed was invented. All new implementation/tests are .om.
